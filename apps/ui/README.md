# 卫星数据工作台 V2.4.3 界面

React、TypeScript 严格检查、Three.js 和 Vite。版本 2.4.3；应用资源由同源本机服务提供，不从 CDN 获取脚本、字体或模型。依赖版本由 `pnpm-lock.yaml` 固定。

新采集仅使用 Three.js 独立隐藏画布生成正式图像。默认深色，可在“设置”切换浅色并通过工作区API保存。页面分为“数据采集”和“任务与结果”：采集页顶部选择模型/模式/保存位置，左侧预览、右侧拍摄设置及分层折叠参数，右栏固定底部的唯一生成动作和草稿重置，左侧预览延伸到下沿；结果页采用左侧任务列表、右侧逐帧图像与冻结信息，噪声参数在独立对话框中配置。任务冻结后端和距离策略，旧数据仍按原规则读取。采集必须保持工作台打开，没有生产Node.js/Playwright依赖。

关闭像素噪声的新采集任务仅保存原图。选择完成任务后，可使用当前像素噪声设置与随机种子“基于原图生成噪声版本”；此操作独立于模型预览与 Blender。新版本复用原始任务的原图、姿态与标签，移动或备份时需同时保留原始任务。

## 数据集保存位置

顶部显示已保存位置，桌面点击“更改”直接选择文件夹，选定即保存，取消或失败保留原位置。浏览器使用简单路径输入与保存。“恢复默认”和目录帮助在设置页。服务验证已有、绝对且可写的目录。“打开文件夹”由原生宿主解析服务端保存位置，任务页可打开冻结的任务目录；消息不接受任意客户端路径。

初次读取设置、选择文件夹和保存期间暂不能提交新采集；已有结果和噪声版本仍可使用。新采集在所选位置创建自己的任务子文件夹；等待中或生成中的任务保持提交时的位置，已有数据不移动。噪声版本始终与原始任务并列保存，不随当前保存位置改变。离线或不可写路径显示错误，不静默改用其他位置。

## 开发与构建

使用 Node.js 24（测试使用原生 TypeScript 类型擦除）和 pnpm：

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm format:check
```

依赖已准备好而 pnpm 启动器无法联网时，可直接运行相同检查：

```powershell
node --test tests/*.test.ts
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build
node node_modules/prettier/bin/prettier.cjs --check src tests *.ts *.json *.yaml *.html *.md
```

生产文件位于 `dist/`，由 Python 服务直接提供。`pnpm dev` 将 `/api`、`/assets/models` 和 `/data` 代理到 `http://127.0.0.1:8765`。

## 坐标与姿态

- 世界系及零姿态本体系均为甲方左手系：X 图像右、Y 朝观测相机、Z 图像上。辅助轴红 X、绿 Y、蓝 Z；零姿态绿色朝相机、蓝色向上。
- 姿态输入为内禀 XYZ 欧拉角，Hamilton 公式、主动 local-to-world 变换。内部数学使用 xyzw 数组；显示和公开 scene API 使用 `sat_quat: { W, X, Y, Z }`，相邻操作保持四元数符号连续。旧 `quaternion_xyzw` 请求被拒绝。
- 仅在目标渲染边界采用 `q_engine = [-x, -z, -y, w]`，等价于交换 Y/Z 的 `R_engine = P R_client P.T`。辅助轴独立应用 P；GLB 保持原有米制引擎坐标和原点，不移动、缩放、反射或重新归一化模型。
- 默认观测相机 CamQuat 为 WXYZ `(0.5, 0.5, -0.5, 0.5)`，其左手坐标为 X 图像上、Y 图像左、Z 光轴朝目标。相机位于甲方世界 `(0,d,0)`，对应引擎 `(0,0,d)`；每个模型使用固定短边 FOV：`2 atan(r / (0.8 sqrt(10000²-r²)))`。
- 拖动调姿使用与拍摄相机同向的观察相机和独立补光，旋转目标并更新客户端四元数；`poseManipulation.ts` 负责轨迹球与内禀XYZ反算，内部保留精度。滚轮只改变观察倍率，正式输出 CamQuat 仍由后端实际观测相机产生。
- V2 协议为 `satellite-pose-4.0` / `lh-client-world-v2`，完整契约见工程 `docs/architecture/interfaces.md`。

## 任务和资源

- 正式图像显示 `/data` 下真实保存的 PNG。改变当前场景不会改动所选任务结果。选择“单张采集”后，右栏底部生成按钮提交一个常规单帧任务；输出目录继续使用 `poses` 命名。
- 覆盖与序列使用服务提供的采样默认值；界面只开放契约支持的参数。
- GLB 内嵌纹理由 Three.js 通过 `fetch(blob:)` 解码，服务 CSP 的 `connect-src` 必须包含 `blob:`。模型、纹理、网络、WebGL 和正式图片错误均有可见提示。
- 快速模型切换取消旧请求，丢弃并释放过期解析结果；卸载时清理动画、控件、纹理、几何、材质和 WebGL 上下文。
- 拍摄视角只在模型材质最终输出中应用灰度；辅助轴始终保留红 X、绿 Y、蓝 Z。拖动调姿关闭同一灰度开关，恢复模型材质颜色。交互预览与正式网页画布分开持有几何、材质、灯光和相机；正式灰度、曝光与噪声以所选后端保存的 PNG 为准。辅助线不进入输出。

- 网页正式配置 `threejs-detail-v1` 固定 Three.js r180、2048²采集、1024²灰度输出、中性环境/补光、ACES 色调映射和自阴影。GLB 哈希、实际相机矩阵、有效几何投影框、配置及抗锯齿实际状态经服务校验后随逐帧姿态发布。完整配置见共享夹具 `tests/fixtures/web-capture-profile.json`。

## 验证范围

自动测试覆盖三轴 ±90°、非对称复合旋转的基变换、q/-q 等价、辅助轴方向及颜色、跨 180° 符号连续、固定球体视场、WXYZ 归一化与嵌套快照冻结，以及旧请求、非有限和越界输入拒绝。实际 WebView2 的 V2 图像、历史 Blender 任务兼容验收由整体验证执行，不将 V1 浏览器记录作为 V2 证明。

Vite 可能提示 Three.js 主包超过默认 500 KB；所有依赖均为本地打包资源。

## 自定义姿态序列

选择“起止姿态序列”，在右侧独立设置起点和终点 XYZ 欧拉角，或记录当前手动姿态。默认 120 帧，包含首尾；数量范围为 2–100000。沿最短旋转路径过渡，相同起止姿态得到静止序列，不表示转一整圈。

播放、暂停或拖动“预览帧”可检查序列。预览期间手动姿态控件禁用；退出后恢复手动姿态。修改端点、帧数或模型会停止并重置预览。当前预览帧的XYZ和四元数同步显示；手动模式支持拖动设定端点，观察缩放保持独立。

右栏底部“生成 N 张图片”冻结完整端点与场景快照，播放位置不改变批量轨迹。四种模式默认明确提交fixed距离策略，20 km可输入10–30 km；覆盖与连续模式可选择automatic。省略策略的历史请求保持原模式规则。数字输入保留编辑草稿，失焦或Enter提交；随机种子和追加噪声状态分开。共享数学向量见tests/fixtures/custom-trajectory-vectors.json。
