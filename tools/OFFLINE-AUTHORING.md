# Separate offline model authoring

The V3.0.0 application captures with Three.js and requires only the registered GLBs. It does not execute Blender, ship Blender scenes, or include authoring utilities in its payload.

`prepare_assets.py`, `build_four_models.py`, `inspect_model_materials.py`, `publish_model_update.py`, `import_curated_models.py`, `import_custom_models.py` and `model_assets/` prepare or inspect source assets offline. Utilities importing `bpy` run only in a separately installed Blender process. Follow the utility's own arguments; these are deliberate source-asset operations rather than application startup steps. They may emit both GLBs and authoring `.blend` files. Keep original source archives, licenses and provenance. Do not replace catalog provenance merely because the application consumes GLB only.

The `verify_v2_*`, `verify_v21_*`, `verify_v22_*`, `verify_v221_benchmark.cjs`, `verify_v23_output_directory.cjs`, `verify_rendering.py`, and `verify_desktop.cjs` entrypoints document historical application behavior and were retired on V2.4. They rely on the removed Blender execution service or older UI. Use the original version checkout to reproduce old checks. Do not rewrite or delete prior reports and task snapshots. Keep `verify_v221_images.py`: besides its historical image audit entrypoint, its geometry decoder is reused by current model import and validation code.

Current native release QA uses `verify_v3_release.cjs`; results and limits are recorded in [verification-v3.0.0.md](../docs/verification-v3.0.0.md). V2.5.2 theme QA remains in [verification-v2.5.2.md](../docs/verification-v2.5.2.md). `verify_v251_models.cjs` covers V2.5.1 model integration; `verify_v250_models_delete.cjs` covers V2.5.0 models and task deletion. Versioned QA tools and reports retain their original scope and should be reproduced against their matching version. Blender runtime/source files retained by older distributions remain separate and are not inputs to the current application dependency lock.
