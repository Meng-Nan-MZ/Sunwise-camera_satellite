# V2.2.1 网页正式采集试用设计

用户已授权实施网页端正式出图，允许重新调整外观，优先细节清楚，速度次要；版本命名 V2.2.1。沿用此前授权：验证后更新 V2 源码分支和版本标签，不制作安装包。V2.2 留作参照，V1 和原工程不改动。

## 方案与范围

选择复用现有 WPF/WebView2 中的 Three.js，不新增生产 Node/Playwright/Chromium 运行库。与直接删除 Blender 相比，保留明确的“Blender 对照”选择便于同姿态验收和回退；与另启无头浏览器相比，复用工作台可减少部署依赖。选择由当前授权的尝试目标和项目条件确定，不再增加确认步骤。

新增“网页出图（细节优先）”，新 UI 默认采用。保留四种采集模式、V2.2 噪声版本和现有坐标协议。只生成正式 PNG/YOLO/姿态 JSON，不引入模型编辑、主题、输出路径或 V1 兼容。网页采集需要保持工作台打开，关闭/断连/上下文丢失须明确中断或失败，不能悄悄切换渲染器。

## 冻结任务与后端

JobRequest 追加 `renderer_backend: "blender"|"threejs"`，缺省为 blender，兼容旧请求/快照；新 UI 显式提交 threejs。字段在 trajectory 之后，避免破坏已有位置参数。snapshot 记录实际选择，公共 Job 返回 renderer_backend；噪声版本公开来源的后端，不允许噪声请求选择新后端。数据协议继续 satellite-pose-4.0 / lh-client-world-v2。

JobRunner 保留现有 renderer_factory 无参注入接口；新增按后端解析/缓存的可选入口，旧工厂只服务 Blender。Three.js 请求不得触发旧工厂。关闭时唤醒网页等待并关闭全部自有渲染器。任务取消立即作废当前网页尝试并唤醒等待；未提交帧不发布，完整已发布帧保留。

Three.js 只要求已验证 SHA256 的 GLB，不要求 Blender 或 .blend。对外 model_sha256 为实际 GLB 的 preview_sha256；Blender 沿用 .blend 哈希。Python 构建 source_to_body，客户端换基只做一次；前端也验证加载字节摘要。渲染元数据记录资产角色、Three revision、配置版本及设置。

## 网页采集桥接合同

后端提供单活动 worker、单活动帧的内存桥接，不给网页传目录/可写路径。全部接口沿用本机 Host/Origin/CSP 限制，能力令牌只在 JSON 请求体中，不进 URL/日志/health。

- `POST /api/render-worker/register`，body `{}`；200 `{worker_token, lease_s:30, heartbeat_interval_s:5}`。重复活动 worker 拒绝409；过期后可重新注册。
- `POST /api/render-worker/heartbeat`，body `{worker_token}`；200确认。心跳与正在进行的载入/渲染独立。
- `POST /api/render-worker/poll`，body `{worker_token}`；最多等待0.25秒，200 `{task:null}` 或 `{task:{task_id,attempt_token,frame,model}}`。model 为已验证 ModelInfo，包含 radius_m、preview_sha256、preview_url、source_to_body（客户端基）；frame 是冻结采样参数。前端串行处理，完成后再领取下一帧。
- `POST /api/render-worker/result`，body `{worker_token,task_id,attempt_token,png_base64,metadata}`，或 `{worker_token,task_id,attempt_token,error}`。200接受；过期/重复/已取消尝试409，错误令牌403。metadata 为 `{bbox_xyxy,camera_world,projection_matrix,asset_sha256,three_revision,profile_id,settings,render_ms}`；矩阵是4行数组，不能误传Three的列主序elements。
- `POST /api/render-worker/release`，body `{worker_token}`，释放并使在途尝试失败。

普通 API 仍限64KiB；仅 result 可接受12MiB JSON、最多8MiB解码 PNG 和64KiB metadata。严格base64、有限JSON、PNG类型、2048²、完整解码、RGB灰度相等且alpha不透明校验后，Python以Lanczos缩至1024并转L，交给原有 prepare_frame/commit_frame 校验及发布。元数据必须匹配当前帧/资产/相机/FOV/投影和固定配置；bbox 使用实际网格顶点，不能用包围球/AABB或图像阈值猜测。

桥接30秒心跳租期、单帧90秒期限，断开/超时明确失败。关闭服务时先设置停止状态、关闭桥接并唤醒短轮询，再等待HTTP处理器，避免退出死锁。取消后迟到的结果不得写入任何已完成帧。

health 保留 renderer_available，新增 `renderers:{blender:{available,reason},threejs:{available,reason}}`。threejs availability 基于工作页成功创建WebGL2并注册的活动租期；Blender基于原配置。UI按所选方式判断提交条件，并显示等待/不可用原因。保留旧测试对 renderer_factory 及 renderer_available 的注入兼容。

## 独立采集场景与细节配置

新建 FormalRenderer，与交互预览不共享可变场景、几何/材质/纹理所有权。缓存当前 GLB（切换时安全释放），无坐标轴/安全框/地面/观察控制，固定正方形采集相机，不等待requestAnimationFrame。pixelRatio=1，内部2048²、请求抗锯齿，最终1024²；记录实际抗锯齿能力与缩采样设置。

固定 profile_id=`threejs-detail-v1`：黑背景、sRGB、ACESFilmic、exposure=1.2；主太阳沿用任务的方向与energy；中性RoomEnvironment填充强度初始0.35；相机固定方向的中性补光初始0.6、方向(-3,2,3)×radius。真实自阴影启用PCFSoftShadowMap，2048贴图，阴影相机按radius拟合。环境/补光属于有意改善细节的仿真设置，全部写入renderer.settings，不将其描述为真实相机标定。实际目视验收可小幅调整强度，变更须同步前后端profile常量和测试。

灰度使用现有模型着色器的0.2126/0.7152/0.0722去色规则。相机固定engine坐标(0,0,d)，upY、朝原点，fov使用captureFov，near=max(.001,d-2r)、far=d+2r+1。目标四元数只应用现有[-X,-Z,-Y,W]适配。实际camera.matrixWorld与projectionMatrix传回，Python独立检查并构造observer_camera。

captureGeometry.projectCaptureBounds(root,camera,resolution=1024)返回连续像素边界[xmin,ymin,xmax,ymax]：应用层级matrixWorld、相机逆矩阵和投影，遍历实际可见网格绘制范围及索引/材质组，拒绝非有限/相机后方/出界/无有效三角形。拒绝未支持的蒙皮、实例、变形或线/点几何，避免静默错误标签。Node用独立已知三角形/层级/相机例子验证；实机再核对六模型。
