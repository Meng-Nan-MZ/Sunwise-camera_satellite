## Intent and approaches

The feedback's fifth item requests changing image output location directly in the UI. The accepted prior proposal adds a remembered dataset location affecting future tasks while old tasks remain accessible; database/logs stay separate.

Changing the whole workspace would fragment task history and restart the service. Moving existing jobs risks large copies and breaks referenced noise data. Builder choice: keep one workspace/database, persist the preferred directory separately and freeze each job's actual storage root. No migration/move/delete of existing data. This is a routine implementation decision within the user's approved scope, not a newly approved user requirement. The implementation proceeds without another confirmation gate.

## User flow

Add a compact dataset save-location panel near collection controls: labeled path input, native “选择文件夹” and “应用” action. Show the effective saved location, busy/error/success feedback and “恢复默认”. Choosing a folder fills the draft; Apply validates and persists it. Canceling the dialog changes nothing. Unsaved text never silently changes a job's destination; show that it is unapplied. The panel explains future captures create their own subfolder and existing tasks stay in place. Standalone browser supports typing/applying; native picker unavailable has a clear desktop-only reason. Do not block existing result/noise access when a preference load/save fails.

The native picker chooses existing directories; users may create a folder using that dialog. Manual Apply requires an existing absolute writable directory. Paths support Chinese, spaces and other drives. Do not auto-create an unavailable drive/directory or silently fall back. File, relative, empty, malformed and unwritable locations give a visible error and preserve the previous saved setting.

Noise variants stay beside their canonical source job, even if the capture preference changed. This retains satellite-noise-1.0 sibling references and allows moving/backing up source+variant together. Explain this exception in UI/docs. No cross-volume source-reference protocol is introduced.

## Storage contract

GET `/api/settings/output-directory` ->200 `{output_directory:string,default_output_directory:string}`. Default is the existing workspace/jobs, not a new C-drive path. POST the same URL accepts exactly `{output_directory:string}` ->200 same result, or400 descriptive validation error. Existing Host/Origin/body protections apply. Saving performs directory resolution/write probe outside the store lock; it changes the setting only after success, in one DB transaction. Missing saved drives remain visible and new captures fail explicitly; no startup fallback rewrites the choice.

JobStore provides `output_settings()->dict`, `set_output_directory(value:str)->dict`, `output_directory(job_id:str)->Path`. Add nullable jobs.output_root and an immutable-root trigger, plus a settings table. Legacy NULL root resolves to workspace/jobs; snapshot content/digests and protocol marker remain unchanged. Every new capture freezes the preferred root before writing the queued job. Every new noise job freezes the canonical source's parent. No output path is added to JobRequest or pose JSON.

All public output_directory, staging, publication and published_file/source resolution derive each job's persisted root. Never derive an old job's destination from the current preference. Validate root access at new-job creation and fail on lost access during rendering; do not redirect. New tasks use `<chosen-directory>/<uuid>/`; defaults and historical layout stay `<workspace>/jobs/<uuid>/`. The selected directory contains only job subdirectories (except the temporary write probe); DB/settings/logs/WebView cache remain in the original workspace. Settings and job creation have a clear short-lock selection boundary; directory probing must not hold the global DB lock. Per-job root updates are forbidden. Existing relative-file allowlist and traversal protection remain effective for external roots.

Changing location is not a general dataset importer or relocation tool. Keep external data directories in place to browse their indexed jobs. Backup the program workspace/database along with dataset roots to preserve task history. Sources and noise siblings stay together.

## Native picker contract

Use .NET8 WPF Microsoft.Win32.OpenFolderDialog, owned by the main window, single selection. No new dependency. UI may send only a correlated message through the existing WebView2:

`{type:'satellite.select-output-directory',request_id:string,initial_directory:string}`

Reply `{type:'satellite.output-directory-selected',request_id:string,path:string|null,error?:string}`. ID nonempty max64, directory max32767, JSON object exact supported request fields. Validate message source against the running service origin, reject unrelated/oversized messages, permit one dialog at a time. Picker only returns a path; it does not save settings, open arbitrary paths, run commands or expose a generic host bridge. Cancel path=null, errors visible and retriable. UI listener correlates IDs and removes listeners on cancellation/unmount; no token in URL. Native absence/cancellation/late unrelated reply are tested. Native requests may take arbitrary user think time; no short timeout that strands a modal dialog.
