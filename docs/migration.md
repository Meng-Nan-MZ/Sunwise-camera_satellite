# 首轮迁移说明

## 文件与依赖边界

新项目放在独立SatelliteDatasetStudio目录中。旧版脚本、Blender安装、RAR原模型和software_workspace原数据没有搬移或覆写。开发配置复用旧版Blender路径；正式交付时由packaging/runtime替代外部引用。不要把旧版根目录直接清空，否则会破坏保留的启动入口。

旧的PowerShell内嵌XAML与BGRA共享内存预览不再进入新界面。Three.js直接载入GLB，Python常规进程管理队列，Blender后台worker独立处理正式图像；同一worker复用模型资源，避免每张重启。

## 六个模型与机体系

INSAT-3B来自旧Hubble.glb并按厘米转米；真正的哈勃来自Hubble_original.glb。其余四个模型使用已有blend_sources中对应的集合以保留正式程序材质。每个模型冻结求值几何，以包围盒中心为旋转原点，保存米制GLB与blend。

三轴沿用导入后右手源场景轴，注册为仿真机体系，不能当作制造商提供的卫星轴标定。模型清单记录变换与来源坐标解释；载荷相机安装默认为仿真假设。购买归档没有新的单翼卫星，当前六模型也未完成单翼类别验收，不通过隐藏面板冒称真实单翼模型。

GLB导出禁止额外坐标轴转换，使其数值坐标与正式blend一致。程序材质无法完整进入glTF，所以实时视图和正式图的材质仍可能不同。正式渲染使用黑色环境、太阳光、Standard视图变换；首轮样图检查后固定曝光为+2 EV，关闭抖动，并逐帧记录。它是可追溯的视觉默认值，尚未完成真实传感器定标。

## 数据协议变化

新数据schema为satellite-pose-3.0，右手世界X右、Y上、Z朝观察者。旧版左手约定仍属于旧schema，不通过重命名字段伪装迁移。六角从合法旋转矩阵导出；连续序列允许四元数w为负，保持相邻符号连续。

拍摄距离独立设置10–30km；固定FOV由最近距离的包围球安全框计算，不再使用distance×occupancy=5，也不随每帧重新调整焦距。SO(3)覆盖集与连续序列分别生成，不声称六个相关角度能够各自独立均匀。

正式PNG经过完整解码，标签相互校验后才记录帧完成。中断产生的未提交文件不会作为完整帧提供下载；已经完成的帧保留。首版中断后重新提交产生新任务，不声称具有逐帧自动续跑。

## 剩余产品验收

- 单翼资产的来源、几何、材质与类别验收。
- 六模型跨姿态的视觉定标，特别是阴影面和金属反射；预览与正式渲染的感知差异。
- 甲方ONNX实际输入输出协议对照；当前协议是已明确记录的仿真约定。
- 独立离线安装包、干净Windows环境与不同显卡验收。
- 长批量运行、磁盘容量与性能基线，以及中断任务从已完成帧继续的工作流。

这些是后续验收范围，不能由一次构建成功替代。本次首先交付整洁工程与可以实际生成新协议数据的完整工作链路。
