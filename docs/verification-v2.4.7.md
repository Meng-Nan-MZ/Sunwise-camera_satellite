# V2.4.7 模型拖动修复验证

日期：2026-11-02。源码基线 `cae448a` / `v2.4.6`。本轮修复拖动交互，保留V2.4.6外观与数量选择，不制作安装包或压缩包。

## 根因与行为约定

基线原生复现记录：`var/verification/v2.4.7-drag-reproduction/1793561416460-79556/report.json`，共11个状态、22张前后截图。

- 随机姿态批量及自动旋转序列被 `manualMode` 条件排除，视口把“允许改采集姿态”同时用作“允许拖动模型”，导致彩色模型预览也无法拖动。该条件在V2.4.5已存在，并非V2.4.6样式遮挡。
- 起止姿态未播放时可以拖动；播放、暂停或逐帧预览使 `customSequence.active` 为真，编辑锁定，只有显式退出后恢复。播放时画面自然变化不代表拖动生效，基线四元数与原X轴插值轨迹吻合。
- 用户已确认：随机姿态批量与自动旋转序列的拖动仅用于查看，保留原批量采集规则。单张及起止姿态继续编辑采集草稿。

## 修复

1. 将视口拖动权限与正式姿态编辑权限分开。随机/自动模式使用独立观察四元数，只传给视口，不能进入正式scene、采样种子、起止端点或提交快照。离开彩色观察、切换模型/采集方式/页面或重置草稿后观察姿态失效。
2. 起止序列播放或暂停时，首次按下拖动会保存当前显示帧到手动草稿并退出序列预览，然后从该姿态连续拖动。已保存起止端点不自动改变，仍通过“使用当前姿态”主动更新。
3. 单张拖动同步XYZ的行为保留。提交期间禁用拖动；灰度“拍摄视角”仍用于查看正式构图，拖动入口是彩色“拖动调姿”或“模型预览”。
4. 更新预览提示和技术详情，明确随机/自动模式中显示的是采集草稿值，拖动只用于观察。固定距离联动、自动变距及旋转预览语义保持原样。

## 验收条件调整与边界

首轮 `1793561691105-87752` 在模型复位的预览像素严格比较处失败。独立探针 `1793561844459-87892` 确认：原生启动DPR为2.25，视口以最多2倍画布绘制；测试设置客户区后DPR变为约1，旧renderer保留2倍缓冲，而切模型新建renderer使用1倍。无拖动重建也产生相同差异；统一DPR后，无拖动重建与拖动后重建的像素严格相同。因此最终验收在设置客户区后，先无拖动切换模型使画布密度一致，再建立基线，没有放宽正式PNG断言，也没有为测试改动生产渲染算法。

验证范围为本机开发版和真实模型交互。没有改写历史任务、V1数据或坐标协议；`KIMI/`仍忽略。V2.4.6记录中的一次原因未知的距离异常不属于本轮已修复结论，其历史记录保持原样。
