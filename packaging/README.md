# V3.0.0 Windows distribution preparation

V3.0.0 uses the bundled Three.js engine in WebView2 for preview and capture. Application payloads include 19 selectable models plus one retired Hubble asset for existing-task compatibility (20 registered `preview.glb` files) and the model catalog; they do not require or ship `.blend` scenes, Blender executables, Blender downloads or Blender source archives. Model catalog provenance and authoring hashes remain unchanged.

This release publishes the V3 source baseline on `main`, the `v3.0.0` tag and a runnable local build. No installer or archive is produced. GLBs and local runtimes remain outside Git; cloning the source repository alone does not provide a complete runnable application. Prepare the authorized assets and runtimes before assembling a distributable.

`dependencies.lock.json` is the application dependency lock. `fetch_dependencies.py --offline` verifies the cached application downloads against their locked SHA256 values. Python, NumPy and Pillow are prepared by `prepare_python.py`; the fixed WebView2 runtime and self-contained .NET publish remain release inputs. Preserve all original dependency licenses.

Local build: run `tools/build-desktop.ps1`, then `tools/start-desktop.cmd`. The build path follows the desktop project version (`var/build/desktop-3.0.0`). Development launch uses explicit project and Python paths and installed WebView2; packaged launch uses fixed WebView2. `var/runtime.json` needs only `python`; obsolete `blender` keys are ignored.

The display name, shortcuts and artifact names use V3. The existing AppId, `Programs/SatelliteDatasetStudioV2` installation directory and `%LOCALAPPDATA%/SatelliteDatasetStudioV2/workspace` remain stable for compatibility. The local workspace remains `var/workspace/`; V3 does not reinterpret existing V2 task snapshots or coordinate protocols. Installer execution and V2-to-V3 shortcut migration are not validated by this source release and must be checked before distributing an installer.

For a future authorized installer release, publish the desktop self-contained for win-x64 to `var/packaging/publish/desktop`, prepare the locked Python and WebView2 inputs, then use `tools/packaging/stage-release.ps1 -Python <python.exe>` to assemble an empty new staging directory. `build_payload.py` verifies model GLB hashes, locked downloads, runtime completeness and self-contained framework metadata, and writes a hashed inventory. `build-installer.ps1 -PayloadDirectory <staging> -Version 3.0.0` validates that inventory before invoking a locally installed Inno Setup 7 compiler. These commands document preparation, not an installer delivered or verified in this release.

Run `python -B -m unittest discover -s tests/packaging -v` for GLB-only fixture assembly, provenance preservation, corruption detection, staging isolation and installer identity checks. Current native release acceptance uses `tools/verify_v3_release.cjs`; results and limits are recorded in `docs/verification-v3.0.0.md`. V2.5.2 default-theme checks remain in `docs/verification-v2.5.2.md`. Native V2.5.1 model acceptance uses `tools/verify_v251_models.cjs`; `tools/verify_v250_models_delete.cjs` retains its V2.5.0 scope. The v246 (`tools/verify_v246_corporate_clean.cjs`), v245, v244, v243, v242 and v241 tools and records retain their original V2.4.6, V2.4.5, V2.4.4, V2.4.3, V2.4.2 and V2.4.1 scopes. The legacy installer functional verifier predates the current UI and is explicitly unavailable for V3.0.0; it must be adapted and validated before publishing a future installer.

## Separate offline authoring and historical evidence

`tools/prepare_assets.py`, `tools/build_four_models.py`, `tools/inspect_model_materials.py`, `tools/publish_model_update.py` and `tools/model_assets/` are authoring utilities, not app runtime dependencies and not copied to payloads. Some authoring utilities use a separately installed Blender. Keep original assets, installed authoring tools, purchased archives and earlier release/source archives unchanged. Original provenance stays in the model catalog. See `tools/OFFLINE-AUTHORING.md`.

Old Blender renderer QA entrypoints are archived reference code and stop with an explicit retirement message on this version. Their recorded historical results remain valid evidence for their original versions; rerunning them against V3.0.0 is unsupported. Installed user data is not removed by uninstall definitions; back up complete task directories before manual data cleanup.
